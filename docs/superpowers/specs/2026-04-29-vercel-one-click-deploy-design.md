# Vercel One-Click Deploy — Design

**Date:** 2026-04-29
**Author:** Sarah Simionescu
**Status:** Approved (ready for implementation plan)

---

## Goal

Make `trustclaw` deployable to Vercel with a single CLI command:

```bash
npx trustclaw deploy
```

The CLI prompts for a Composio API key, auto-generates secrets, auto-provisions Postgres (and optionally Redis) via Vercel Marketplace, forks the repo into the user's GitHub, creates the Vercel project, sets env vars, and triggers deploy.

## Non-goals

- Custom domain configuration (user does that in Vercel UI later)
- Multi-region or multi-instance deployment topology
- Self-hosted (non-Vercel) deploy automation
- Backwards compatibility with the current Google OAuth or Anthropic SDK direct usage

---

## Architectural changes from current state

### 1. Replace direct LLM SDK usage with Vercel AI Gateway

**Why:** AI Gateway authenticates via Vercel's auto-generated OIDC token when deployed on Vercel — zero env vars for LLM/embedding access. Eliminates the need for users to obtain Anthropic and OpenAI API keys.

**Current state:**
- Agent uses Anthropic SDK directly (`anthropic.messages.create(...)`) in `src/server/api/routers/trustclaw/agent/setup.ts` and elsewhere
- Embeddings use the OpenAI SDK directly via `src/server/clients/openai.ts`

**Target state:**
- All LLM calls use `generateText` / `streamText` / `streamObject` from `ai` with model strings like `'anthropic/claude-sonnet-4.6'` (gateway routes via OIDC)
- All embedding calls use `embed` / `embedMany` from `ai` with `'openai/text-embedding-3-large'`
- Delete `src/server/clients/openai.ts`
- Delete `@ai-sdk/anthropic` direct usage; use plain string model ids

**Model IDs (verified via gateway API):**
- Chat: `anthropic/claude-sonnet-4.6`
- Embeddings: `openai/text-embedding-3-large` (with `dimensions: 1024` to match the existing `composio_claw_memory` schema)

### 2. Replace Google OAuth with Better Auth username plugin

**Why:** Username/password requires zero external setup — only the DB (already required). Users skip Google Cloud Console entirely.

- Remove `socialProviders.google` from `src/server/auth.ts`
- Remove `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` from `src/env.ts`
- Add Better Auth `username` plugin from `better-auth/plugins`
- Replace login UI with username + password form
- Add a register/sign-up flow (single-user typical, but keep open for multi-user self-hosters)

### 3. Drop CRON_SECRET, use Vercel-cron header verification

**Why:** Vercel cron requests carry `user-agent: vercel-cron/1.0`. Comparing against this is sufficient and removes one secret to manage.

- Remove `CRON_SECRET` from env schema
- In every cron route handler under `src/app/api/cron/trustclaw/`, replace the bearer-token check with:
  ```typescript
  const ua = request.headers.get('user-agent') ?? '';
  if (!ua.startsWith('vercel-cron')) {
    return new Response('Unauthorized', { status: 401 });
  }
  ```

### 4. Make optional env vars actually optional

Change schema in `src/env.ts` from `z.string()` to `z.string().optional()` for:
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_BOT_USERNAME`
- `TELEGRAM_WEBHOOK_SECRET`
- `TWITTER_AUTH_CONFIG`
- `REDIS_URL`

Add runtime guards at every consumer:
- Telegram routes / webhook handlers / bot-init code: if `!env.TELEGRAM_BOT_TOKEN`, return early or render "Telegram not configured" UI
- Twitter toolkit code path: omit `twitter` from the Composio `authConfigs` object when the env var is unset
- Resumable streams: if `!env.REDIS_URL`, fall back to non-resumable `streamText`. The chat still streams; refresh-mid-stream just loses the in-flight response.

### 5. Final env var matrix

| Var | Required | Auto-provisioned | Notes |
|---|---|---|---|
| `DATABASE_URL` | ✅ | ✅ Neon Postgres via Marketplace | Must have pgvector extension |
| `BETTER_AUTH_SECRET` | ✅ | ✅ Generated by CLI | 32-byte random |
| `COMPOSIO_API_KEY` | ✅ | ❌ User pastes in CLI | Free tier signup ~30 sec at composio.dev |
| `REDIS_URL` | ❌ | Optional via Marketplace | CLI prompts "Add Redis for resumable streams? [Y/n]" |
| `TELEGRAM_*` | ❌ | ❌ | Set later in Vercel UI to enable Telegram |
| `TWITTER_AUTH_CONFIG` | ❌ | ❌ | Set later to enable Twitter toolkit |

Removed entirely: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `CRON_SECRET`, `RESEND_API_KEY` (already gone).

```

  ✓ Validated

? Add Redis for resumable streams? (recommended) [Y/n] Y

  ✓ Forked

> Creating Vercel project "trust-claw"...
  ✓ Project created

> Provisioning Neon Postgres (Marketplace)...
  ✓ Connected DATABASE_URL

> Provisioning Upstash Redis (Marketplace)...
  ✓ Connected REDIS_URL

> Setting environment variables...
  ✓ BETTER_AUTH_SECRET (auto-generated)
  ✓ COMPOSIO_API_KEY (your input)

  ✓ Build queued
  ✓ Deployment URL: https://trust-claw-sarahsimionescu.vercel.app

```

### Implementation

- New directory: `cli/` (or top-level `src/cli/` — TBD during planning)
- Standalone npm package OR script run via `pnpm dlx`
- Stack: TypeScript + `commander` (or just plain `process.argv` parsing) + `prompts` for interactivity + `chalk` for colors
- Uses **Vercel REST API** (`api.vercel.com`) with the user's token (obtained via `vercel login` flow or by detecting an existing `~/.vercel/auth.json`)
- Uses **GitHub REST API** via `gh` CLI subprocess OR direct HTTP with the user's token from `gh auth token`
- Auto-generates `BETTER_AUTH_SECRET` via `crypto.randomBytes(32).toString('base64')`

### CLI flow (high level)

1. **Auth**: detect or prompt for Vercel login (`vercel login`) and GitHub auth (`gh auth status`)
2. **Inputs**: prompt for `COMPOSIO_API_KEY`, "Add Redis? [Y/n]"
3. **Generate**: `BETTER_AUTH_SECRET = crypto.randomBytes(32).toString('base64')`
4. **Fork**: `POST https://api.github.com/repos/<source>/forks` to fork into the user's account
5. **Create Vercel project**: `POST https://api.vercel.com/v9/projects` with `gitRepository` linking to the forked repo
6. **Provision Postgres**: connect Neon Postgres via Marketplace API, capture connection string, set as `DATABASE_URL`
7. **Provision Redis** (if opted-in): same flow with Upstash, capture as `REDIS_URL`
8. **Set env vars**: `POST https://api.vercel.com/v10/projects/{id}/env` for each: `BETTER_AUTH_SECRET`, `COMPOSIO_API_KEY`
9. **Run schema migration**: trigger a Vercel build hook OR run `prisma db push` locally with the captured `DATABASE_URL` (the latter is simpler)
10. **Trigger deploy**: `POST https://api.vercel.com/v13/deployments` (production)
11. **Poll until ready**, print final URL

### Open implementation questions (defer to planning)

- Whether to use Vercel CLI subprocess (`vercel link`, `vercel deploy --prod`) vs raw REST API. CLI subprocess is easier; REST API is more transparent.
- Marketplace integration auto-provisioning: the exact REST endpoint shape for "create Neon Postgres for this project" — needs research during plan-writing. Fallback if it's painful: have CLI print "Visit this URL to provision a database" and pause for user.
- Username plugin signup flow: does the username plugin auto-create the first user, or does the user register via UI after deploy? UI seems cleaner.

## Risks & mitigations

1. **Vercel Marketplace auto-provisioning may require manual user click-through** — even with the API, Neon/Upstash integrations may show a consent screen. **Mitigation:** CLI opens browser to consent screen, waits for user to approve, then continues. If too painful, document as a manual step.

2. **`prisma db push` from the CLI requires the DATABASE_URL to be reachable from the user's machine** — Neon URLs are public-internet-routable so this should work.

3. **AI Gateway OIDC token requires the deployment to be on Vercel** — local dev needs `vercel env pull` to get a short-lived OIDC token (12-hour validity). **Mitigation:** Document this in CLAUDE.md and README. Optionally: support a `AI_GATEWAY_API_KEY` fallback for local dev.

4. **Username plugin UX for "first user"** — does the deploy land on a register page or a login page when the DB is empty? **Mitigation:** add a check: if zero users exist, redirect `/login` → `/register`.

5. **`@ai-sdk/anthropic` removal may break things** — the codebase may depend on Anthropic-specific provider options. **Mitigation:** AI Gateway supports passing provider-specific options via `providerOptions: { anthropic: { ... } }`. Audit during planning.

## Verification

- **Smoke test path post-deploy:**
  1. CLI completes successfully
  2. Visit deployed URL → register page shows
  3. Register with username + password → land on dashboard
  4. Complete onboarding → set agent identity
  5. Send a message → agent responds (verifies AI Gateway via OIDC works)
  6. Tell agent a fact, refresh, ask the fact → agent recalls (verifies memory + embeddings via gateway)

- **Local dev still works** with `vercel env pull` providing a short-lived OIDC token, or with a manually-set `AI_GATEWAY_API_KEY`.

## Out of scope

- Custom domain setup
- Multi-region/edge deployment
- Migrating existing TrustClaw users (this is a fresh OSS fork — no migration needed)
- Self-hosted Postgres/Redis instructions (deferred)
- Stripe billing for end-users of self-hosted instances (was already removed in the prior refactor)
